## Overview

`devices.apps.getConfig` computes the effective app configuration for a given device configuration ID. It merges configuration values from the relevant level defaults and device-specific overrides and returns a single, resolved view of what the device should see.

<Callout kind="info">

Type: Query — `devices.apps.getConfig` is implemented as a Convex query in `convex/devices/apps.ts`.

</Callout>

The returned configuration includes metadata about where each setting came from, such as whether a value was inherited from a level or explicitly set on the device. This lets you inspect not just the final value but also its source.

## Purpose

Use `devices.apps.getConfig` whenever you need the current, effective app configuration for a device, rather than raw level or device records. The query centralizes the merge logic so that both backend and frontend consumers rely on the same rules for precedence between level defaults and per-device overrides.

On the frontend, the App Store project reads this data through `deviceAppConfig` in `src/hooks/useAppCategories.ts`, using `useQuery(api.devices.apps.getConfig, ...)`. That hook drives the App Store settings and category-filter UI based on the device’s current configuration, ensuring the UI always reflects the resolved configuration that the backend will enforce.
